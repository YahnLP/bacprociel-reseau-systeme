## Partie C – Filtrer vers le serveur (ACL, ≈ 40 min)

> [!EXAMPLE]+ 🚀 Pour aller plus loin
> Ce passage va **au-delà du référentiel** : il est utile au métier, mais **non exigé à l'épreuve terminale**.

**But :** sur `R1`, depuis le réseau des postes, n'autoriser **que le web** (HTTP et HTTPS) vers le serveur, et **compter** ce qui est refusé.

❓ **Avant d'écrire l'ACL : sur quelle interface la poses-tu, dans quel sens (`in` ou `out`), et pourquoi ?** ______________________

<details markdown="1"><summary>💡 Aide : la structure de l'ACL (à compléter toi-même)</summary>

Une ACL **étendue nommée** : trois lignes (deux `permit tcp` du réseau des postes vers l'**hôte** du serveur, ports 80 et 443, puis `deny ip any any log`), appliquée avec `ip access-group … in` sur l'interface côté postes. Voir [CCNA 5-03](../../ccna/5-03-acl/01-cours.md) si tu veux aller plus loin.

```text
ip access-list extended WEB-ONLY
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.20.100 eq 80
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.20.100 eq 443
 deny ip any any log
interface gi0/0
 ip access-group WEB-ONLY in
```

</details>

**Prédis** avant de tester :

| Test depuis `PC1` | Prédiction | Résultat |
|---|---|---|
| Web (`curl http://192.168.20.100`) | | |
| `ping 192.168.20.100` | | |
| `ping 192.168.20.1` (le routeur lui-même) | | |

Regarde `show access-lists` : **quelles règles ont des « matches » ?** ______________________

❓ **Pourquoi le dernier `deny ip any any` est-il important (et que se passerait-il sans lui) ?** ______________________

<details markdown="1"><summary>Aide</summary>

Sur un routeur Cisco, une ACL a toujours un **refus implicite** à la fin. Écrire `deny ip any any log` le rend **visible** et **compte** les refus.

</details>

✅ **Point de contrôle :** le **web marche**, le **ping vers le serveur échoue** (« Communication administrativement filtrée »).

## 🔍 Dépannage

| Symptôme | Cause probable | Que faire |
|---|---|---|
| `crypto key generate` refusé | Pas de nom de switch / pas de `ip domain-name` | Faire `ip domain-name …` d'abord |
| SSH : `Login invalid` | Mauvais nom ou mot de passe | Retaper `admin` + mot de passe |
| Après l'ACL, le web ne marche plus | Règle `permit` mal écrite (adresse, port) | `show access-lists`, comparer avec la mise en place |
| L'ACL ne filtre rien | Pas appliquée à l'interface | `ip access-group WEB-ONLY in` sur `gi0/0` |
| Tout est bloqué, même le web | Mauvais sens (`in` / `out`) ou mauvaise interface | Vérifier `show ip interface gi0/0` |
| `ufw` : plus d'accès SSH | Activé sans règle 22 | Console de la VM : `sudo ufw allow 22/tcp` |

➡️ **Mission en entreprise :** faire le point avec le tuteur sur 3 bonnes pratiques.
