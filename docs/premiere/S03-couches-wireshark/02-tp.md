## Partie A – Un ping dans le même réseau (≈ 30 min)

1. Dans l'analyseur, **Effacer**. Choisis **Capture sur : `PC1 Eth0 ↔ SW1 P1`**.
2. Depuis `PC1`, lance `ping 192.168.10.12`.
3. Mets le filtre `icmp` puis **Appliquer**. Clique sur **une requête** (`Echo (ping) request`).
4. Dans le détail, **ouvre** *Ethernet II*, *Internet Protocol*, *Internet Control Message Protocol*, puis remplis :

| Couche | Champ | Valeur lue |
|---|---|---|
| Ethernet | Source (MAC) | |
| Ethernet | Destination (MAC) | |
| Ethernet | Type | |
| IP | Source | |
| IP | Destination | |
| IP | TTL | |
| IP | Protocole | |
| ICMP | Type | |

✅ **Point de contrôle :** la **MAC destination** est celle de `PC2` (pas celle de la passerelle) : **même réseau**.

## Partie B – ARP : qui a cette adresse ? (≈ 30 min)

1. Dans `PC1`, **vide le cache ARP** : `arp -d *` *(ou fais **RAZ réseau** dans le simulateur et recharge le fichier)*.
2. **Efface** l'analyseur. Lance `ping 192.168.10.12`.
3. Filtre `arp`. Remplis :

| N° de trame | Qui envoie ? | À qui ? | Que dit la trame ? |
|---|---|---|---|
| 1ʳᵉ | | | |
| 2ᵉ | | | |

4. Tape `arp -a` sur `PC1` : quelle ligne a été **ajoutée** ? ______________________

✅ **Point de contrôle :** tu peux expliquer **pourquoi la 1ʳᵉ trame est en diffusion** et la 2ᵉ non.

<details markdown="1"><summary>Aide</summary>

La 1ʳᵉ trame : destination `Broadcast` (`ff:ff:ff:ff:ff:ff`) ; la 2ᵉ : `PC2` répond **directement** à `PC1`, dont il connaît maintenant la MAC (elle est dans la requête).

</details>

**🔁 Échange des rôles.**

## Partie C – À travers le routeur (≈ 50 min)

C'est **le cœur** du TP.

1. **Efface** l'analyseur. Depuis `PC1`, lance `ping 192.168.20.100`.
2. **Capture 1** : *Capture sur* `PC1 Eth0 ↔ SW1 P1` (segment 1). Filtre `icmp`, clique sur **une requête**. Remplis la colonne « Segment 1 ».
3. **Capture 2** : *Capture sur* `SRV2 ens33 ↔ R1 Gi0/1` (segment 2). Même trame (même `seq`) : remplis la colonne « Segment 2 ».

| Champ | Segment 1 (PC1 ↔ SW1) | Segment 2 (R1 ↔ SRV2) | Change ? |
|---|---|---|---|
| MAC source | | | |
| MAC destination | | | |
| IP source | | | |
| IP destination | | | |
| TTL | | | |

✅ **Point de contrôle :** **seules** les MAC et le TTL changent ; les IP sont identiques.

❓ **Quelle est la MAC destination sur le segment 1 ? À qui appartient-elle ?** ______________________

❓ **Quel équipement a diminué le TTL ? De combien ?** ______________________

<details markdown="1"><summary>Aide</summary>

Compare avec tes MAC relevées en début de TP. La MAC destination du segment 1 est celle de **`R1` (Gi0/0)**. Le TTL passe de **128** (départ Windows) à **127** : `R1` a retiré 1.

</details>

4. **Schéma à compléter** : sur une feuille, dessine `PC1 — R1 — SRV2` et **note au-dessus de chaque segment** les MAC et IP source / destination de la trame.

**🔁 Échange des rôles.**

## 🔍 Dépannage

| Symptôme | Cause probable | Que faire |
|---|---|---|
| L'analyseur est vide | Capture arrêtée / mauvais lien sélectionné | Redémarrer la capture ; choisir *Toutes les liaisons* |
| Pas de trame ARP | Le cache ARP est déjà rempli | **RAZ réseau**, ou `arp -d *` |
| Trop de trames | Pas de filtre | Taper `icmp` ou `arp` puis **Appliquer** |
| `ping 192.168.20.100` échoue | Fichier modifié | Recharger [`p03-couches.json`](tp/p03-couches.json) |
| Je ne trouve pas le TTL | Détail IP non ouvert | Cliquer sur *Internet Protocol* ; défiler |
