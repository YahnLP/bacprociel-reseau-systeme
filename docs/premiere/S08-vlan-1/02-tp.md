## Partie B – Créer les VLAN (≈ 30 min)

**But :** deux réseaux logiques, `10 DIRECTION` et `20 ATELIER`.

🤔 **J'anticipe.** Quand j'aurai créé les deux VLAN, **`PC3` joindra-t-il encore `PC1` ?** Où seront les ports Fa0/1 à Fa0/4 ? Mon pronostic : ______________________

<details markdown="1"><summary>💡 Aide : la syntaxe</summary>

`configure terminal`, puis `vlan 10` et `name DIRECTION`, `exit`, idem pour le VLAN 20, puis `end` et `show vlan brief`.

</details>

| Question | Réponse |
|---|---|
| Quels ports sont dans le VLAN 10 maintenant ? | |
| Le ping de `PC3` vers `PC1` marche-t-il **toujours** ? Pourquoi ? | |

> [!IMPORTANT]
> **Créer un VLAN ne change rien tant qu'aucun port n'est affecté.** Les ports sont encore tous dans le VLAN 1.

✅ **Point de contrôle :** `show vlan brief` affiche `10 DIRECTION` et `20 ATELIER` (sans port).

**🔁 Échange des rôles.**

## Partie C – Affecter les ports (≈ 30 min)

**But :** `Fa0/1` et `Fa0/2` dans le VLAN 10 ; `Fa0/3` et `Fa0/4` dans le VLAN 20. **Deux manipulations suffisent** (pense aux plages de ports).

<details markdown="1"><summary>💡 Aide : la syntaxe</summary>

`interface range fa0/1 - 2`, puis `switchport mode access` et `switchport access vlan 10`. Même chose pour `fa0/3 - 4` avec le VLAN 20. Vérifie avec `show vlan brief` et `show interfaces status`.

</details>

🤔 **Remplis la colonne « Prédiction » du tableau ci-dessous AVANT de faire les tests.**

✅ **Point de contrôle :** `show vlan brief` : `Fa0/1, Fa0/2` dans le VLAN 10 ; `Fa0/3, Fa0/4` dans le VLAN 20.

| Test (avec **les mêmes adresses 192.168.1.x**) | Prédiction | Résultat |
|---|---|---|
| `PC1` → `PC2` | | |
| `PC3` → `PC4` | | |
| `PC1` → `PC3` | | |
| `PC4` → `PC2` | | |

❓ **Les adresses IP n'ont pas changé : qu'est-ce qui sépare maintenant `PC1` de `PC3` ?** ______________________

<details markdown="1"><summary>Aide</summary>

Le switch ne transmet une trame qu'**entre les ports du même VLAN**. `PC1` fait un ARP pour trouver `PC3` : la diffusion n'atteint que le VLAN 10.

</details>

Observe la **table MAC** : `show mac address-table` (après un ping). **Une colonne a changé par rapport au S05 : laquelle ?** ______________________

**🔁 Échange des rôles.**

## Partie D – Un VLAN = un sous-réseau (≈ 30 min)

Les deux services partagent encore la même plage : c'est une mauvaise pratique. **Re-adresse** :

| Poste | Nouvelle adresse | Masque |
|---|---|---|
| `PC1`, `PC2` | 192.168.**10**.11 et .12 | 255.255.255.0 |
| `PC3`, `PC4` | 192.168.**20**.13 et .14 | 255.255.255.0 |

✅ **Point de contrôle :** `PC1` ↔ `PC2` et `PC3` ↔ `PC4` répondent encore ; `PC1` ne joint pas `PC3`.

❓ **Pourquoi y a-t-il maintenant deux raisons indépendantes pour que `PC1` ne joigne pas `PC3` ?** ______________________

🔍 **J'observe.** Que montrent `show vlan brief` et `show interfaces status` pour `Fa0/1` ? Qu'est-ce qui m'a surpris ? ______________________

Sauvegarde : `write memory` sur `SW1`, puis **enregistre** dans le simulateur (`TP-S08-tonnom.json`).

| **Quel port est dans le mauvais VLAN ?** | |

<details markdown="1"><summary>Aide 1 – où regarder</summary>

`show vlan brief` donne **la liste des ports de chaque VLAN**. Compare-la au tableau de la mise en place.

</details>

<details markdown="1"><summary>Aide 2 – les commandes</summary>

Pour **déplacer** un port : `interface fa0/…` puis `switchport access vlan …`. Pour **un port oublié**, il faut aussi `switchport mode access`.

</details>

## 🔍 Dépannage

|---|---|---|

| Le VLAN n'apparaît pas dans `show vlan brief` | Pas créé | `vlan 10` + `name …` |
| `% Invalid input` sur `switchport access vlan` | Mauvais mode | Se placer dans `interface …` |
