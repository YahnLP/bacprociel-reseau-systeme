# 🛠️ TP – Un plan d'adressage VLSM

*Parcours CCNA – Domaine 1 – module 1-04 – individuel ou binôme*

> [!NOTE]
> **Mission.** Une petite entreprise a reçu le réseau `192.168.50.0/24`. Le **service A** compte environ **50 postes**, le **service B** environ **25 postes**, et les deux routeurs sont reliés par un lien. Tu dois **découper** le réseau, **configurer** les routeurs et les postes, puis **prouver** que A et B communiquent.
>
> **Temps prévu :** 45 min. **Prérequis :** [cours 1-04](01-cours.md).

> [!NOTE]
> **Comment ce TP fonctionne.** Les **commandes et réglages sont donnés** quand on ne peut pas les deviner : ton travail est de les **comprendre** (que fait chaque ligne, pourquoi, comment je le vérifie). Écris tes réponses aux ❓ **avant** de tester. Le **bilan final** nourrit ton **passeport d'autonomie**.

## Partie B – Configurer les routeurs (≈ 15 min)

Sur `R1` :

```text
enable
configure terminal
interface gi0/0
 ip address <passerelle de A> <masque>
 no shutdown
 exit
interface gi0/1
 ip address <1ʳᵉ adresse du lien> <masque>
 no shutdown
 exit
ip route <réseau B> <masque B> <adresse de R2 sur le lien>
end
```

Fais l'équivalent sur `R2`, avec la route statique vers le réseau A.

✅ **Point de contrôle :** `show ip route` sur `R1` affiche une ligne `C` par réseau connecté et une ligne `S` vers le réseau B.

---

## Partie C – Configurer les postes (≈ 10 min)

Sur `PC-A` : `sudo ip addr add <adresse>/<préfixe> dev ens33` puis `sudo ip route add default via <passerelle>`.
Même chose sur `PC-B`.

---

## Partie D – Prouver (≈ 10 min)

1. `ping` de `R1` vers `R2` sur le lien.
2. `ping` de `PC-A` vers `PC-B`.
3. `traceroute` de `PC-A` vers `PC-B` : combien de sauts ?

| Test | Résultat |
|---|---|
| R1 → R2 (lien /30) | |
| PC-A → PC-B | |
| Nombre de sauts | |

✅ **Point de contrôle final :** PC-A joint PC-B et tes trois blocs ne se chevauchent pas.
