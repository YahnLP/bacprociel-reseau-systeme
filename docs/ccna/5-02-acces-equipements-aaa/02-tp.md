# 🛠️ TP – Durcir l'accès à un switch

*Parcours CCNA – Domaine 5 – module 5-02 – individuel*

> [!NOTE]
> **Mission.** Un switch vient d'arriver, **sans aucune protection**. Tu le sécurises : mot de passe privilégié haché, compte local, bannière, AAA locale et lignes vty protégées.
>
> **Temps prévu :** 30 min. **Prérequis :** [cours 5-02](01-cours.md).

> [!NOTE]
> **Comment ce TP fonctionne.** Tu as un **but** et des **contraintes**. Les **commandes sont données** quand on ne peut pas les deviner : ton travail est de les **comprendre** (ce que fait chaque ligne, pourquoi dans cet ordre, comment tu le vérifies). Écris ta réponse aux 🤔 et ❓ **avant** de tester. Le **bilan final** nourrit ton **passeport d'autonomie**.

## Partie A – Constater (≈ 5 min)

Sur `SW1` : `enable` → aucun mot de passe demandé. `show running-config` : repère les lignes de sécurité.

🤔 **J'anticipe :** que risque-t-on si ce switch est branché ainsi dans un bureau ? Qui pourrait s'y connecter et que pourrait-il faire ? ______________

---

## Partie B – Configurer (≈ 15 min)

**But :** que personne ne puisse administrer ce switch sans s'authentifier, et qu'aucun mot de passe ne soit lisible dans la configuration.

**Contraintes :**
- mot de passe du mode privilégié : `Cisco#2027`, **haché** ;
- compte local `admin` / `Pa55w0rd!`, également **haché** ;
- une **bannière** d'avertissement : `Acces reserve aux personnes autorisees` ;
- l'authentification passe par **AAA locale** et s'applique aux lignes **vty 0 4** (accès à distance) ;
- configuration sauvegardée.

<details markdown="1" open><summary>📌 Les commandes (à comprendre, pas à recopier)</summary>

```text
configure terminal
enable secret Cisco#2027
username admin secret Pa55w0rd!
banner motd #Acces reserve aux personnes autorisees#
aaa new-model
aaa authentication login default local
line vty 0 4
 login local
 end
write memory
```

</details>

Ferme la session (`exit`) puis rouvre-la : `enable` doit maintenant demander le mot de passe.

| Question | Réponse |
|---|---|
| Quelle différence entre `enable secret` et `enable password` ? | |
| À quoi sert la ligne `aaa authentication login default local` ? | |
| Dans `show running-config`, le mot de passe `enable secret` est-il lisible ? | |
| Que fait chaque ligne `aaa …` et `login local` ? Que se passerait-il si on oubliait `login local` sous `line vty` ? | |
| Pourquoi un compte **nominatif** vaut-il mieux qu'un mot de passe partagé ? | |

✅ **Point de contrôle final :** `enable` demande le mot de passe, et `show running-config` ne montre aucun mot de passe en clair pour `enable` et `admin`.

## 🧊 Alternative avec Cisco Packet Tracer

> [!TIP]
> Le simulateur du site **ne mémorise pas** : `service password-encryption`, le mot de passe de la console, `exec-timeout`. Packet Tracer les accepte :
>
> ```text
> service password-encryption
> line console 0
>  password Console#27
>  login
>  exec-timeout 5 0
> ```
>
> Compare `show running-config` avant et après `service password-encryption`.
