## Partie B – Passer en SSH (≈ 40 min)

**But :** n'autoriser que **SSH** pour administrer `R1`, avec un **compte nominatif** `tech` (mot de passe `Tech#2027`).

**Contraintes :** SSH **version 2** ; les lignes `vty 0 4` n'acceptent que SSH et authentifient avec les comptes **locaux** ; configuration sauvegardée.

<details markdown="1" open><summary>📌 Les commandes (à comprendre, pas à recopier)</summary>

```text
ip domain-name garage.local
username tech privilege 15 secret Tech#2027
crypto key generate rsa modulus 1024
ip ssh version 2
line vty 0 4
 transport input ssh
 login local
```

</details>

## Partie C – Publier l'intranet (≈ 40 min)

**But :** que le technicien voie l'intranet **depuis Internet**, sans que le serveur ait une adresse publique.

**Contraintes :** on utilise **le port 8080** de l'adresse WAN `203.0.113.3`, redirigé vers **`192.168.1.10` port 80** ; le port 80 du WAN ne doit **pas** répondre.

<details markdown="1" open><summary>📌 La syntaxe (à comprendre)</summary>

```text
ip nat inside source static tcp <ip-interne> <port-interne> <ip-publique> <port-externe>
```

Les interfaces doivent aussi être déclarées `ip nat inside` (LAN) et `ip nat outside` (WAN).

</details>

✅ **Points de contrôle :**
- depuis `DISTANT` : `http://203.0.113.3:8080` affiche « Intranet du garage Dupuy » ;
- `http://203.0.113.3` (port 80) **ne répond pas** ;
- `show ip nat translations` montre la redirection.
