# 🛠️ TP – Mettre en service un partage de fichiers, puis un NAS

*Parcours serveurs – module 3 – binôme*

> [!NOTE]
> **Mission.** Un cabinet comptable veut un **espace partagé** : le groupe *compta* lit et écrit, la *direction* lit seulement, les autres n'ont **rien**. Tu le montes d'abord **à la main** (Samba), tu le casses et le dépannes, puis tu le refais **avec OpenMediaVault** et tu prouves qu'une **sauvegarde** se restaure.
>
> **Temps prévu :** 4 h (2 séances). **Prérequis :** [cours 3](01-cours.md), instantané `point-zero`, la [méthode](../methode-depannage.md).

> [!NOTE]
> **Comment ce TP fonctionne.** Les **commandes et réglages sont donnés** quand on ne peut pas les deviner : ton travail est de les **comprendre** (que fait chaque ligne, pourquoi, comment je le vérifie). Écris tes réponses aux ❓ **avant** de tester. Le **bilan final** nourrit ton **passeport d'autonomie**.

## Le cahier des charges

| Compte | Groupe | Droit attendu sur `\\serveur\commun` |
|---|---|---|
| `alice` | `compta` | **lire et écrire** |
| `bob` | `compta` | **lire et écrire** |
| `chef` | `direction` | **lire seulement** |
| `stagiaire` | aucun | **aucun accès** |

> [!TIP]
> Avant de toucher au clavier, **réfléchis** : combien de **groupes** faut-il ? Comment donner « lecture seule » à la direction **avec les droits Linux** ? (indice : un dossier = **un** propriétaire, **un** groupe, et « les autres ».) Note ta conception, **puis** seulement implémente.

## Partie B – Réalisation avec Samba (≈ 60 min)

1. Crée les comptes, les groupes, les mots de passe SMB et le dossier `/srv/partage/commun` selon ta conception.
2. Écris `smb.conf`, valide avec `testparm`, redémarre `smbd`.
3. **Teste chaque ligne du tableau** depuis `smbclient` **et** depuis Windows (`\\adresse\commun`) :

```bash
smbclient //adresse/commun -U alice -c "put fichier.txt; ls"
```

## Partie C – Pannes à diagnostiquer (≈ 50 min)

Binôme : l'un provoque, l'autre **diagnostique avec fiche**. Instantané avant.

| # | Provocation | Symptôme à identifier |
|---|---|---|
| 1 | `sudo smbpasswd -x alice` (supprime son mot de passe SMB) | `NT_STATUS_LOGON_FAILURE` |
| 2 | Retire `bob` du groupe `compta` (`sudo gpasswd -d bob compta`) | `NT_STATUS_ACCESS_DENIED` |
| 3 | Mets `read only = yes` puis `sudo smbcontrol smbd reload-config` | connexion OK, écriture refusée |
| 4 | Renomme le bloc `[commun]` en `[communs]` | `NT_STATUS_BAD_NETWORK_NAME` |
| 5 | `sudo chmod 750 /srv/partage/commun` | écriture refusée pour les membres du groupe |
| 6 | `sudo systemctl stop smbd` | connexion impossible |

| Question | Réponse |
|---|---|
| Pour la panne 3 **et** la panne 5, le message est identique : comment les **distingues-tu** ? (quelle commande, quel niveau) | |
| Après correction de la panne 2, faut-il autre chose côté utilisateur pour que ça marche ? | |
| Sous Windows, comment oublier des identifiants mémorisés ? | |

## Partie D – Le même partage avec OpenMediaVault (≈ 60 min)

1. Nouvelle VM `NAS` : Debian 64 bits, **2 Go de RAM**, un disque système de 8 Go **et un second disque de 10 Go** (données), carte NAT + privé hôte. Installe **OpenMediaVault** avec l'ISO fournie.
2. Interface web (`http://adresse/`) : **change tout de suite le mot de passe administrateur** (les identifiants d'origine sont publics).
3. Réalise le **cahier des charges** avec l'interface : système de fichiers (créer, **monter**), utilisateurs et groupes, dossier partagé et droits, service SMB et partage.
4. Rejoue le **tableau de tests** de la partie B.

| Question | Réponse |
|---|---|
| Pour chaque étape faite dans l'interface, **quelle commande** ou **quelle directive** correspond ? (tableau de 4 lignes minimum) | |
| Où voir le **journal** d'OMV / de Samba pour comprendre une erreur ? (en SSH sur la VM) | |

> [!WARNING]
> Les noms de menus d'OMV changent selon la version : suis les rubriques *Stockage*, *Gestion des accès*, *Services*. **Ne perds pas de temps sur l'interface** : si une option manque, retrouve la **directive** correspondante.

## Partie E – Sauvegarde et restauration (≈ 40 min)

1. Ajoute un **troisième disque virtuel** (`/mnt/sauvegarde`, système de fichiers monté).
2. Copie le partage : `rsync -a --dry-run /srv/partage/ /mnt/sauvegarde/` (**observe**), puis sans `--dry-run`.
3. **Supprime** un fichier du partage, puis **restaure-le** depuis la sauvegarde.
4. Simule une **erreur** : supprime le fichier, lance `rsync -a --delete` : que devient la copie ?

| Question | Réponse |
|---|---|
| Que montre `--dry-run` ? Pourquoi est-ce une bonne habitude ? | |
| Après l'étape 4, peux-tu restaurer le fichier ? Que faudrait-il pour qu'une suppression accidentelle ne se répercute pas ? | |
| En **3-2-1**, qu'est-ce qui te manque ici ? | |
| Le disque de données tombe en panne : RAID 1, instantané ou sauvegarde, lequel te sauve ? Et pour un fichier supprimé hier ? | |
