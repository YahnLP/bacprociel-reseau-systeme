# 🛠️ TP – Un domaine pour une petite entreprise : conception, installation, GPO, dépannage

*Parcours serveurs – module 4 – binôme*

> [!NOTE]
> **Mission.** Une entreprise de 12 postes veut centraliser ses comptes. Tu **conçois** l'annuaire, tu **installes** le contrôleur de domaine, tu **joins** un poste, tu appliques des **GPO**, puis tu **dépannes** des pannes provoquées.
>
> **Temps prévu :** 5 h (3 séances). **Prérequis :** [cours 4](01-cours.md), [module 0](../m0-virtualbox/02-tp.md), la [méthode](../methode-depannage.md). **À valider avec ton enseignant** : ISO, version de Windows Server, noms de menus.

> [!NOTE]
> **Comment ce TP fonctionne.** Les **commandes et réglages sont donnés** quand on ne peut pas les deviner : ton travail est de les **comprendre** (que fait chaque ligne, pourquoi, comment je le vérifie). Écris tes réponses aux ❓ **avant** de tester. Le **bilan final** nourrit ton **passeport d'autonomie**.

## Partie B – Préparer puis installer (≈ 60 min)

1. Renomme le serveur `SRV-AD`, fixe son adresse IP, vérifie l'**heure** et le **fuseau**.
2. Installe le rôle AD DS (**sans** promouvoir) : `Install-WindowsFeature AD-Domain-Services -IncludeManagementTools`.
3. **Prends un instantané `avant-promotion`**.
4. Promeus le serveur : **nouvelle forêt** `entreprise.local`, DNS installé. Note le mot de passe DSRM.
5. Après redémarrage, **vérifie** :

```powershell
dcdiag
nslookup -type=SRV _ldap._tcp.dc._msdcs.entreprise.local
Get-Service NTDS, DNS, Kdc
```

## Partie D – Joindre un poste (≈ 30 min)

1. Sur `CLIENT` : IP fixe, **DNS = 192.168.56.10**. Vérifie : `ping 192.168.56.10`, `nslookup entreprise.local`.
2. Joins le domaine (*Paramètres système → Domaine*) avec un compte autorisé. Redémarre.
3. Ouvre une session `ENTREPRISE\alice`, puis `whoami` et `echo %USERDOMAIN%`.
4. **Observe** sur `SRV-AD` : où est apparu le compte d'ordinateur `CLIENT` ? **Déplace-le** dans l'OU de ton choix.

## Partie F – Pannes à diagnostiquer (≈ 60 min)

> [!WARNING]
> **Règle du binôme :** l'un provoque (sur le contrôleur et/ou le client), l'autre **diagnostique avec fiche**, sans connaître la cause. **Instantanés** de `SRV-AD` **et** de `CLIENT` avant, **restaurés ensemble** après.

| # | Provocation | Symptôme à identifier |
|---|---|---|
| 1 | Sur `CLIENT`, mets le DNS à `8.8.8.8`, puis tente d'ouvrir une session de domaine / de rejoindre le domaine | domaine introuvable |
| 2 | Décale l'**heure** de `CLIENT` de 20 minutes (hors synchronisation) | échec d'authentification |
| 3 | Déplace `carole` dans le conteneur `Users` | la GPO « panneau de configuration » ne s'applique plus |
| 4 | Dans la GPO « Lecteur Compta », remplace la **configuration utilisateur** par un réglage de la **configuration ordinateur** | le lecteur n'apparaît plus pour `alice` |
| 5 | **Désactive** le compte `bob` | connexion impossible, message explicite |
| 6 | Arrête le service DNS sur `SRV-AD` | le poste ne retrouve plus le domaine |

|---|---|
