# 🛠️ TP – Préparer une VM serveur, la casser, la réparer

*Parcours serveurs – module 0 – individuel*

> [!NOTE]
> **Mission.** Tu construis la VM de référence des modules suivants, tu vérifies **chaque couche**, puis tu provoques trois pannes classiques et tu les diagnostiques avec la [méthode](../methode-depannage.md).
>
> **Temps prévu :** 2 h. **Prérequis :** [cours 0](01-cours.md). Garde une [fiche de dépannage](../fiche-depannage.md) ouverte.

> [!NOTE]
> **Comment ce TP fonctionne.** Les **commandes sont données** quand on ne peut pas les deviner : ton travail est de les **comprendre** (que fait chaque ligne, pourquoi dans cet ordre, comment je le vérifie). Écris tes réponses aux 🤔 et ❓ **avant** de tester. Le **bilan final** nourrit ton **passeport d'autonomie**.

## Partie A – Créer la VM (≈ 30 min)

1. VirtualBox : *Nouvelle*. Nom `SRV-LINUX`, type Linux, **Debian 64 bits**, **1 Go de RAM**, disque de **10 Go**.
2. *Paramètres → Stockage* : monte l'ISO Debian (ou Ubuntu Server).
3. Installe en choisissant « serveur SSH » et « utilitaires usuels du système », **sans** environnement de bureau.

| Question | Réponse |
|---|---|
| Pourquoi 1 Go de RAM suffit-il ici ? Que se passerait-il avec 256 Mo ? | |
| Pourquoi pas d'interface graphique sur un serveur ? | |

## Partie B – Les deux cartes réseau (≈ 20 min)

1. *Fichier → Outils → Gestionnaire de réseau* : crée un **réseau privé hôte** s'il n'en existe pas.
2. VM éteinte, *Paramètres → Réseau* : **Carte 1** en NAT, **Carte 2** en réseau privé hôte.
3. Démarre, ouvre une session et relève :

```bash
ip -br a
ip r
ping -c 2 8.8.8.8
```

| Question | Réponse |
|---|---|
| Adresse et nom de l'interface de la carte NAT ? | |
| Adresse et nom de l'interface de la carte privé hôte ? | |
| Quelle est la passerelle par défaut ? Par quelle carte sort-on sur Internet ? | |

> [!TIP]
> Si la carte 2 n'a pas d'adresse : `sudo dhclient <interface>` (ou configure-la selon ta distribution). Dis-toi à voix haute **pourquoi** : sur le réseau privé hôte, c'est en général VirtualBox qui joue le rôle de serveur DHCP (s'il est activé sur ce réseau).

## Partie C – Vérifier couche par couche (≈ 15 min)

Remplis ce tableau en lançant **les commandes** :

| Couche | Test | Résultat |
|---|---|---|
| Machine | `df -h` et `free -h` : espace libre / mémoire libre | |
| Réseau | `ping -c 2 192.168.56.1` (le PC hôte, selon ton adressage) | |
| Internet | `ping -c 2 8.8.8.8` | |
| Nom | `ping -c 2 debian.org` | |
| Paquets | `sudo apt update` | |
| Accès à distance | depuis le PC : `ssh utilisateur@adresse` | |

Puis **prends l'instantané `point-zero`** (*Machine → Prendre un instantané*).

## Partie D – Casser pour comprendre (≈ 45 min)

Pour chaque panne : **provoque-la**, puis **diagnostique comme si tu ne savais pas** (fiche de dépannage), corrige, vérifie. *(Un binôme peut provoquer la panne à l'insu de l'autre.)*

### Panne 1 – Plus de passerelle

🤔 **J'anticipe :** si je supprime la route par défaut, pourrai-je encore joindre le PC hôte (`192.168.56.1`) ? Et `8.8.8.8` ? Pourquoi ? ______________

```bash
sudo ip route del default
ping -c 2 8.8.8.8
```

| Question | Réponse |
|---|---|
| Que renvoie `ping` ? Quel message exact ? | |
| Quelle commande montre la cause ? | |
| Correction (avec la bonne adresse de passerelle) ? | |

### Panne 2 – Le nom ne se résout plus

🤔 **J'anticipe :** quel ping marchera encore, quel ping échouera, et pourquoi ? ______________

```bash
sudo cp /etc/resolv.conf /tmp/resolv.conf.bak
echo "nameserver 192.0.2.1" | sudo tee /etc/resolv.conf
ping -c 2 8.8.8.8 ; ping -c 2 debian.org
```

| Question | Réponse |
|---|---|
| Pourquoi l'adresse répond-elle mais pas le nom ? | |
| Que dit ce test sur la couche en cause ? | |
| Correction : restaure `resolv.conf` (`sudo cp /tmp/resolv.conf.bak /etc/resolv.conf`). Pourquoi ce fichier peut-il être réécrit automatiquement ? | |

### Panne 3 – Un service ne tourne plus

```bash
sudo apt install -y nginx
sudo systemctl stop nginx
curl -I http://localhost
```

| Question | Réponse |

| `ss -tlnp` : le port 80 est-il à l'écoute ? | |
| Quelle commande répare ? Que faut-il de plus pour que ça survive à un redémarrage ? | |
