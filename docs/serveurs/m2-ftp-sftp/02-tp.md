# 🛠️ TP – Un serveur de dépôt sécurisé : de FTP à SFTP, avec dépannage

*Parcours serveurs – module 2 – binôme*

> [!NOTE]
> **Mission.** Une petite entreprise veut que ses clients **déposent des fichiers**. Tu installes d'abord FTP pour **comprendre**, tu constates ses faiblesses, puis tu proposes la bonne solution (**SFTP cloisonné**) et tu la dépannes.
>
> **Temps prévu :** 3 h. **Prérequis :** [cours 2](01-cours.md), instantané `point-zero`, Wireshark sur le PC, la [méthode de dépannage](../methode-depannage.md).

> [!NOTE]
> **Comment ce TP fonctionne.** Les **commandes sont données** quand on ne peut pas les deviner : ton travail est de les **comprendre** (que fait chaque ligne, pourquoi dans cet ordre, comment je le vérifie). Écris tes réponses aux 🤔 et ❓ **avant** de tester. Le **bilan final** nourrit ton **passeport d'autonomie**.

## Partie A – Installer vsftpd (≈ 30 min)

```bash
sudo apt update && sudo apt install -y vsftpd
sudo cp /etc/vsftpd.conf /etc/vsftpd.conf.origine      # sauvegarde AVANT de modifier
```

Écris une configuration **minimale et sûre** (voir cours §3), crée l'utilisateur `eleve1`, prépare `/home/eleve1/depot` (racine `root:root` 755, sous-dossier à `eleve1`), puis :

```bash
sudo systemctl restart vsftpd
sudo ss -tlnp | grep :21
```

## Partie C – Pannes FTP à diagnostiquer (≈ 45 min)

> [!WARNING]
> **Règle du binôme :** une personne provoque, l'autre **diagnostique avec fiche de dépannage**, sans voir la modification. Instantané avant de commencer.

| # | Provocation (serveur) | Symptôme à identifier |
|---|---|---|
| 1 | `sudo chown eleve1:eleve1 /home/eleve1` | login OK puis erreur `500` |
| 2 | `write_enable=NO` puis `restart` | dépôt refusé (`550`) |
| 3 | `sudo chmod 555 /home/eleve1/depot` | dépôt refusé (`553`) |
| 4 | `sudo passwd eleve1` (nouveau mot de passe non communiqué) | `530 Login incorrect` |
| 5 | `sudo systemctl stop vsftpd` | connexion refusée |

| Question | Réponse |
|---|---|

| Quelle différence de **code** entre la panne 2 et la panne 4 ? Que t'apprend-elle ? | |
| Dans le journal `/var/log/vsftpd.log`, quelle ligne correspond à la panne 3 ? | |

## Partie D – La bonne solution : SFTP cloisonné (≈ 45 min)

1. Désactive FTP : `sudo systemctl disable --now vsftpd`.
2. Installe/active SSH : `sudo apt install -y openssh-server`.
3. Ajoute le bloc `Match User eleve1` du cours (`ChrootDirectory /home/eleve1`, `ForceCommand internal-sftp`) **dans un second terminal gardé ouvert**, puis :

```bash
sudo sshd -t && sudo systemctl reload ssh
```

4. Depuis le PC : `sftp eleve1@adresse`, `ls`, `put`, `get`. Essaie ensuite `ssh eleve1@adresse`.
5. Refais la capture Wireshark (filtre `ssh`).

| Question | Réponse |
|---|---|
| Que lis-tu maintenant dans la capture ? | |
| Que répond `ssh eleve1@adresse` ? Pourquoi est-ce voulu ? | |
| Que voit `eleve1` à la racine ? Peut-il aller dans `/etc` ? | |
| Que se passe-t-il si `/home/eleve1` appartient à `eleve1` ? **Teste-le**, note le symptôme côté client et le message côté serveur (`journalctl -u ssh`). | |
